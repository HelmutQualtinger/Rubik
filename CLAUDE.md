# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single self-contained `index.html` implementing a fully interactive 3x3x3 Rubik's Cube with Three.js (loaded via CDN + import map — no build step, no package.json, no dependencies to install). Open the file directly in a browser to run it.

## Development

- Run: open `index.html` in any modern browser (or `python3 -m http.server` and visit it — needed only if testing module/CORS behavior, plain `file://` works fine here since Three.js is loaded from a CDN import map).
- There is no build, lint, or test tooling in this repo. Verify changes by loading the page and checking the browser console, or by driving it headlessly with Playwright (`chromium.launch()` → `page.goto('file://.../index.html')`) to check for `pageerror`/console errors and take screenshots.
- Three.js version is pinned in the `<script type="importmap">` block (currently `three@0.169.0`, resolved from `unpkg.com`). Bump the version there — and in the `three/addons/` path — together; addon modules (OrbitControls, RectAreaLightUniformsLib, RoomEnvironment) come from the same `examples/jsm/` tree and must stay in lockstep with core.

## Architecture

Everything lives in one `<script type="module">` block at the bottom of `index.html`, structured top to bottom as:

1. **Constants & color table** — `SPACING`/`CUBIE`/`STICKER_INSET` control cubie geometry and gaps; `COLORS` maps face keys (U/D/R/L/F/B) to sticker hex colors; `TURN_MS` (460ms) is the base manual-turn duration — scramble and solve pass their own shorter `duration` per move so mass turning stays brisk.
2. **Audio** (`ensureAudio`, `playClick`, `playSolvedChime`) — every sound is synthesized with the Web Audio API at call time, no audio files. `playClick()` layers a short bandpassed noise burst (the transient) with a decaying low sine (the "thock") and is called once per turn from inside `rotateLayer`, with a small random pitch offset per call for a less mechanical, more organic click train during scramble/solve. `playSolvedChime()` fires a 4-note triangle-wave arpeggio from `onSolved()`. Browsers require an `AudioContext` to be created/resumed from within a genuine user-gesture handler, so `ensureAudio()` is called synchronously at the top of the `pointerdown` listener and every control-button `click` handler — never lazily from inside an animation callback. The `soundEnabled` flag (toggled by `#sound-toggle`) gates both functions.
3. **Renderer/scene/camera/OrbitControls** — standard Three.js boilerplate. A procedural `RoomEnvironment` is baked via `PMREMGenerator` into `scene.environment` specifically so the brushed-metal materials (metalness-heavy, no diffuse response) have something to reflect.
4. **Lighting rig** — a hemisphere light plus `RectAreaLight`s positioned above/below/side for soft, diffuse illumination, and one dim `DirectionalLight` kept only to cast a soft ground-contact shadow (`sun`).
5. **Materials** — `stickerTexture()`/`brushedTexture()` generate canvas textures at runtime (rounded-rect sticker color, directional brush-noise bump map); `stickerMaterial()` is memoized per color in `stickerMatCache` and `plasticMat` is shared by every cubie body.
6. **Cube data model** (`cubies` array + `buildCube()`): 27 `THREE.Group`s on an integer grid `x,y,z ∈ {-1,0,1}`, each holding one black body mesh plus one sticker `Mesh` per exterior face. Each cubie tracks its logical grid position in `.pos`, independent of its Three.js transform.
7. **Layer rotation** (`rotateLayer`, `integerRotate`, `snapTransform`): to turn a layer, matching cubies are reparented onto a temporary pivot `Group` via `pivot.attach()` (preserves world transform), the pivot is animated one axis by ±90°, then cubies are reparented back with `cubeRoot.attach()` and their `.pos` updated via a hand-rolled integer rotation matrix. Positions/quaternions are snapped to exact grid values afterward to prevent floating-point drift from compounding over many turns. `queueMove()` serializes turns so overlapping animations (e.g. during scramble) never race on `.pos`. Every completed turn is also pushed onto `history` as `{axis, layerValue, dir}` unless the caller passes `record:false`, and triggers `playClick()`.
8. **Solve detection** (`checkSolved`): for each of the 6 global faces, finds — per cubie in that layer — whichever sticker's *current world-space normal* points closest to that face's axis (not which sticker was originally assigned there), then checks all 9 are the same color. This makes it orientation-agnostic and correct after arbitrary scrambling. A sticker's world normal is `child.userData.localNormal` (its fixed outward direction *in the cubie's local space*, cached once at build time) rotated by **the cubie group's** current world quaternion — not the sticker mesh's own `getWorldQuaternion()`, which would double-apply the sticker's local rotation and silently never detect a solve. (This was a real bug once; if solve detection ever stops firing, check here first.)
9. **Pointer interaction & turn-direction detection**: `pointerdown` raycasts against cubie bodies only; if it hits one, `OrbitControls` is disabled and a drag session starts, recording the grabbed face's world-space normal axis/sign and the exact 3D grab point. If `pointerdown` misses all cubies, `OrbitControls` handles it natively for camera orbit. A grabbed face can only be turned about the two axes lying in its own plane (the two axes other than its normal), each turnable ±90° — 4 candidate moves — so once `pointermove` clears a small pixel threshold, the code disambiguates in one shot: for each of the 2 candidate axes it computes the 3D direction a point at the grab location would move under a small *positive* rotation about that axis (`tangent = axis × normal`, i.e. `v = ω × r` with `r` approximated by the face normal), projects both the grab point and grab point + tangent through the camera to get that motion as a 2D screen direction, and dots it against the actual on-screen mouse-drag vector. The axis with the larger `|dot|` is the one being turned; the *sign* of that dot gives the direction (positive = drag agrees with the positive-rotation tangent → `dir:+1`; negative → `dir:-1`). See the comment block above the `pointermove` listener for the full derivation. This resolves the whole gesture from a single sample on the *first* threshold crossing (a discrete "flick," not continuous drag-following rotation).
10. **Scramble/Solve/Reset/stats**: `scramble()` fires a sequence of un-counted `rotateLayer` calls through the same queue (still recorded to `history`, still clicking). `solveCube()` is a pure undo stack: it pops the entire `history` array, reverses it, and replays each move with `dir` negated and `record:false` — no cube-solving algorithm involved, so it always reaches solved regardless of what produced the current state. `buildCube()` is called again wholesale on Reset (which also clears `history`) rather than reversing moves. The **Solve** button (`#btn-solve`) is disabled whenever `history` is empty via `updateSolveButtonState()`. Move counter and timer are plain module-level state updated from `rotateLayer`'s completion callback, gated by that call's `countMove` flag (true for manual drags, false for scramble/solve moves).

## Key invariants to preserve when editing

- A cubie's `.pos` (integer grid coordinate) must always be updated *after* its animation finishes and its transform is snapped — never optimistically.
- Any new geometry that needs correct outward-facing normals for `checkSolved()` must have `userData.face` and `userData.localNormal` set the same way `buildCube()`/`patchAllNormals()` do it now, and must be read via the **parent cubie group's** world quaternion, not the sticker mesh's own (see point 7 above).
- Keep face-turn animations going through `queueMove()`, not `rotateLayer()` directly, whenever more than one turn might be in flight (scramble, programmatic sequences) — `rotateLayer()` alone has no race protection.
- Any programmatic move sequence that should be undoable by the **Solve** button must go through `rotateLayer()` with `record` left at its default (`true`); pass `record:false` only for moves that are themselves undoing history (as `solveCube()` does), or they'll re-enter `history` and corrupt the undo order.
- After changing anything in `buildCube()`, remember `history` and `moveCount`/timer state are *not* reset automatically — only the Reset button clears them.
- Any new way of triggering a turn (new button, keyboard shortcut, etc.) must call `ensureAudio()` synchronously inside its own user-gesture event handler before anything async happens — calling it later (e.g. inside a `.then()` or `rotateLayer`'s own logic) will leave the `AudioContext` suspended in most browsers and every sound will silently no-op.
